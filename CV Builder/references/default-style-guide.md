# Default CV Style Guide

This is the default layout this skill uses when either:

1. **No prior CV exists** to model formatting from, or
2. **A prior CV exists but uses a two-column or sidebar layout** — a
   graphic-heavy column running alongside the main content (common in
   template-driven resume builders). That layout is a default to actively
   move away from, not preserve, for two concrete reasons: applicant
   tracking systems parse left-to-right, top-to-bottom, and frequently
   garble or drop content sitting in a side column entirely; and a sidebar
   crowds contact info, skills, or dates into a narrow strip that's harder
   to scan than a clean vertical flow.

If a prior CV already uses this single-column pattern, match it rather
than reinventing it — this guide is the fallback, not a mandate to
override a working format.

## Structure

```
[FULL NAME]
[Address] · [Phone]
[Email] · [LinkedIn] · [Website]

[Optional: 3-5 sentence professional summary, first person, plain
language — what they do, how they work, what they're known for. Skip
this if the person doesn't want one; it's a strong default, not
mandatory.]

Experience Overview

[Company] | [Location]
[Date range] | [Title]
- [Bullet, verb-first, number in the first clause if one exists]
- [Bullet]
- [Bullet]

[Company] | [Location]
[Date range] | [Title]
- [Bullet]

  (If a second role existed at the same company, list it directly
  beneath without repeating the company/location line:)
[Date range] | [Title]
- [Bullet]

Education

[Date range]
[Degree] – [Focus, if relevant]
[Institution] – [Location]

Skills
[Grouped by theme, not a flat alphabetical dump — e.g. "Partner
ecosystem operations," "Marketing automation," "Event production."
A simple two-column list is fine here specifically, at the very bottom,
for compactness — this is different from a full-page two-column layout
and doesn't cause the same ATS problems since skills are typically
short keyword phrases rather than sentences needing reading order.]
```

## Formatting rules

- Single column for the body of the document — no sidebar, no colored
  background blocks, no icon-based section markers.
- One consistent font family throughout, minimal color (a single accent
  color for name/headings is fine, body text stays neutral).
- Bold used for: name, company names, role titles, date ranges. Not for
  entire bullet lines.
- Bullets are left-aligned, consistent bullet character throughout.
- Reverse chronological order, always.
- Multiple roles at the same company nest under one company header rather
  than repeating it — see structure above.
- Keep margins and spacing consistent enough that the document reads as
  one coherent system, not a patchwork of differently-styled sections.

## When producing an actual file

If the person wants a downloadable Word document, check and follow the
`docx` skill's guidance for implementation — this style guide describes
the target layout and content hierarchy; the `docx` skill handles the
mechanics of producing a clean, properly-formatted `.docx` file from it.
